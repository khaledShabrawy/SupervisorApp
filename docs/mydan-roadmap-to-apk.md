# Mydan — الخطة الشاملة من الويب إلى APK

## 1) الهدف النهائي

تحويل التطبيق الحالي من تطبيق ويب PWA إلى تطبيق Android APK قابل للتثبيت، مع الحفاظ على نفس النطاق التجاري والوظيفي:

- متابعة مشرف المبيعات داخل الشركة
- تسجيل الزيارات
- مراجعة الرف
- تقييم المنافسين
- إدارة العملاء
- متابعة الأهداف
- إشعارات داخل التطبيق
- لوحة إدارة للمشرفين/المدير

ملاحظة مهمة: التطبيق لا يشمل أي مبيعات أو فواتير أو تحصيل أو عربات مالية. لا توجد أي وظائف مالية داخل التطبيق أو داخل مسار التحويل إلى APK.

---

## 2) الحالة الحالية

المشروع الآن في وضع جيد من الناحية التقنية:

- Frontend React + Vite
- Web PWA
- Supabase كخادم بيانات و auth
- RTL عربي بالكامل
- إدارة وصول المشرفين حسب الشركة
- هيكل شاشات وظيفية جاهز
- اختبارات تلقائية للمنطق الأساسي موجودة
- البناء الإنتاجي يعمل بشكل صحيح

نقطة البداية الحالية: تطبيق ويب جاهز ومختبر، ويتطلب الآن تحويله إلى Android APK بطريقة آمنة ومتماشية مع المتطلبات التجارية.

---

## 3) النطاق النهائي المطلوب

### 3.1 التطبيق الرئيسي
- تسجيل الدخول بحساب Supabase
- اختيار الشركة / التحقق من حساب المشرف
- عرض لوحة التحكم اليومية
- إدارة الزيارات
- بدء زيارة ومتابعة الرحلة
- مراجعة الرف
- التحقق من المنافسين
- إدارة العملاء
- إعداد الأهداف ومتابعة التقدم
- إشعارات داخلية
- لوحة الإدارة

### 3.2 ما لا يضاف
- أي طلبات بيع أو أوردرات مالية
- أي فواتير أو مجموعات مالية
- أي تحصيل أو إيرادات
- أي أزرار أو جداول تمس المال
- أي تحويل لنظام native غير web-based في النطاق الأساسي

---

## 4) المرحلة 1 — تثبيت أساس التطبيق Web وتهيئة النطاق

### الأهداف
- تأكيد أن الكود الحالي مطابق للنطاق النهائي
- حذف أي بقايا أو شاشات لا تتوافق مع المنتج
- توحيد اللغة والهيكل والوظائف

### المهام
- مراجعة جميع ملفات src
- التأكد من أن كل route يطابق النطاق
- إزالة أي مراجع أو صفحات مالية أو بيعية
- التحقق من سلامة اسم المشروع وواجهته
- إغلاق أي نقاط غير مكتملة في المصادقة أو الأذونات

### خروج المرحلة
- تطبيق web متوافق بنسبة 100% مع النطاق
- لا توجد مراجع مالية أو بيع في الكود
- جميع الاختبارات تمر بنجاح

---

## 5) المرحلة 2 — إعداد التطبيق ليكون Android-ready

### الهدف
- تحويل التطبيق الحالي إلى تطبيق يمكن تثبيته على Android عبر wrapper Android native
- الحفاظ على نفس المنطق والواجهة دون إعادة بناء كاملة للفكرة

### التقنية المقترحة
- استخدام Capacitor لتغليف تطبيق الويب داخل Android WebView
- أو Android Studio مع WebView إذا رغبت في حل مبسط
- الحفاظ على PWA كقاعدة أساسية، ثم إرفاقه داخل Android shell

### مميزات هذا الطريق
- تقليل التكلفة والوقت
- إبقاء نفس الكود الخاص بالواجهة
- سهولة تحديث التطبيق لاحقًا
- تبسيط دورة النشر والتحديث

### المهام
- تجهيز ملف تكوين Capacitor
- ربط التطبيق الحالي مع تطبيق Android
- إعداد app ID و package name
- إعداد splash screen و icons
- إعداد status bar والألوان الخاصة بالشركة
- إعداد permissions الأساسية
- ربط التطبيق بملف Supabase كواجهة خادم

### خروج المرحلة
- تطبيق Android shell يعمل ويتضمن نفس التطبيق
- يمكن تشغيله محليًا على Android Emulator أو جهاز فعلي

---

## 6) المرحلة 3 — التوافق مع المحمول

### الأهداف
- تحسين تجربة المستخدم على الهاتف
- ضبط الواجهات للهواتف المحمولة
- ضمان التفاعل الطبيعي مع زر العودة، شريط الحالة، والأجهزة المحمولة

### مهام هامة
- تحسين الأزرار والهوامش
- ضبط المسافات للهواتف الصغيرة
- التأكد من أن القوائم سريعة ومرنة
- التحقق من حالة عدم الاتصال
- تحسين الوقت اللازم للتحميل الأول
- التحقق من التثبيت عبر PWA قبل Android shell

### نقطة مهمة
- إذا تم إضافة Android wrapper، يجب أيضا مراعاة أن التطبيق يبقى متوافقًا مع Web و Mobile بشكل كامل.

---

## 7) المرحلة 4 — المصادقة والأمان في التطبيق المحمول

### الأهداف
- إبقاء الأمان على نفس مستوى الويب
- التحقق من المستخدم والامتيازات داخل التطبيق

### المهام
- مراجعة Supabase Auth داخل التطبيق المحمول
- التأكد من أن التحقق من المشرف والحالة النشطة يعمل داخل Android shell
- الحفاظ على company_id والمعايير حسب الشركة
- منع الدخول بدون حساب صالحة
- منع الوصول عبر جلسة من شركة أخرى

### قواعد الأمان
- لا تسمح بفتح التطبيق بدون جلسة
- لا تسمح بالتحايل على company_id
- لا تسمح بتجاوز ربط المشرف بحسابه الحقيقي
- لا تسمح بتحميل بيانات شركة أخرى

---

## 8) المرحلة 5 — المزامنة والـ Offline و Notifications

### الحاجة
التطبيق الميداني غالبًا يحتاج إلى التفاعل أثناء التنقل، ولذلك يجب تضييق الفجوة بين الاتصال والانقطاع.

### المهام
- تحسين التخزين المحلي عند انقطاع الإنترنت
- تخزين البيانات قبل إرسالها أو عند إعادة الاتصال
- ضبط قفل البيانات عند فشل الشبكة
- تهيئة الإشعارات المحلية داخل الهاتف
- دعم إشعارات الخلفية متى توفرت

### الحالة المطلوبة
- التطبيق يعمل بدون اتصال في حدود محددة
- لا يفقد حالة المستخدم أو الشركة
- الإشعارات تظهر بشكل صحيح وفق الأولوية

---

## 9) المرحلة 6 — الاحتفاظ بالهوية المؤسسية

### الهدف
إنشاء هوية متكاملة للشركة الأولى، وهي شركة زينة الورقيات، مع إمكانية التوسع لاحقًا.

### المهام
- اسم التطبيق الرسمي: Mydan
- اللون الأساسي المناسب لشركة الزينة
- شعار الشركة في واجهة الدخول
- إعدادات خاصة بالشركة متغيرة لاحقًا

### مبدأ التصميم
- branding هو عنصر قابل للتخصيص
- auth و data isolation لا يخلط مع branding
- لا تلتزم بواجهة واحدة في كل شركة، بل بجهاز متوافق مع شخصيات الشركات المختلفة

---

## 10) المرحلة 7 — اختبار الجودة قبل APK

### يجب أن يمر التطبيق بهذه الاختبارات قبل تحويله إلى APK

#### اختبار الوظائف الأساسية
- تسجيل الدخول
- الخروج
- تخصيص الشركة
- الصفحة الرئيسية
- الزيارات
- مراجعة الرف
- المهام داخل الزيارة
- المنافسون
- العملاء
- الأهداف
- اللوحة الإدارية

#### اختبار الأمان
- تسجيل دخول غير مصرح له
- محاولة الوصول لبيانات شركة غير متعلقة
- جلسة منتهية
- محاولة الوصول إلى routes المحظورة

#### اختبار العمليات الميدانية
- حالة عدم اتصال
- حالة تكرار الشبكة
- حفظ البيانات عند إعادة الاتصال
- حالة إعادة تحميل الصفحة

#### اختبار Android
- تثبيت التطبيق
- التشغيل الأول
- استقبال الإشعارات
- تحميل الصور
- اتمام الزيارات والمهام

## 11) المرحلة 8 — بناء APK النهائي

### الخطوات
1. التأكد من أن التطبيق يعمل بشكل كامل على الويب
2. تجهيز Capacitor أو Android Studio wrapper
3. إعداد Android project
4. ضبط package name و app name
5. إضافة icons و splash screen
6. اختبار التطبيق على emulator
7. بناء APK release
8. اختبار APK على هاتف فعلي
9. رفع النسخة النهائية إلى متجر أو توزيع داخلي

### ملحوظة مهمة
- APK لا يساوي إطلاق متجر رسمي، بل أول خطوة للخط الإنتاجي الكامل
- يمكن استخدام APK كنسخة تجريبية أو داخلية في بداية التنفيذ

---

## 12) المرحلة 9 — النشر والإطلاق

### بعد بناء APK
- وضع نسخة التجريبية Internal Testing
- جمع تقارير المستخدمين
- مراجعة أول 20-30 استخدام فعلي
- إصلاح نقاط التوقف
- توسيع النطاق تدريجيًا

### المراحل التالية بعد APK
- تحسين لوحة التقارير
- أدوات إدارة الشركات
- دعم مديرين أكثر من شركة
- زيادة الأتمتة في الملاحظات
- دعم جميع الشركات داخل نفس المنصة

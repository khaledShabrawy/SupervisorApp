# ميدان — بناء Android APK للمشرفين

الهدف الذي أكده المالك: **تطبيق Android يُسلَّم للمشرفين كملف APK قابل للتثبيت**. واجهة React الحالية تُدمج داخل Capacitor؛ لوحة الإدارة تظل واجهة ويب. نجاح بناء Vite وحده لا يعني استخراج APK.

يحافظ التطبيق على المهام والزيارات والعملاء ومراجعات الرف والمنافسين والأهداف التشغيلية والإشعارات. الطلبات والأسعار والأهداف المالية مخفية، والكود والبيانات التاريخية محفوظة.

## أدوات البناء

- Node 24 وpnpm 10.26.1.
- **JDK 21 كامل** يحتوي `java` و`javac`؛ اضبط `JAVA_HOME`.
- Android SDK Platform 35 وBuild-Tools 34.0.0؛ اضبط `ANDROID_HOME` أو `ANDROID_SDK_ROOT`، أو `sdk.dir` في `artifacts/mydan/android/local.properties`.
- يستخدم المشروع Gradle Wrapper 8.11.1 وAndroid Gradle Plugin 8.7.2 الموجودين في المستودع. قد يحتاج أول بناء إلى تنزيل تبعياتهما.
- إعدادات Supabase العامة المعتمدة للبناء. لا تضع مفاتيح الخدمة أو أسرار المزودين في متغيرات `VITE_*`.

لا يقوم سكربت البناء بقبول تراخيص SDK نيابة عن المالك، أو إنشاء مفتاح Release، أو رفع أي ملف أو تغيير قاعدة البيانات.

## الأوامر من جذر المستودع — Windows وLinux وmacOS

```sh
pnpm install --frozen-lockfile
pnpm android:doctor
pnpm apk:debug
```

`apk:debug` يفحص الأدوات، يبني واجهة Android الحالية، يزامنها محليًا مع Capacitor، ينظف النسخ المولدة من ملفات APK/PWA غير المناسبة، ثم يشغّل `assembleDebug`.

الناتج عند نجاح البناء:

```text
artifacts/mydan/android/app/build/outputs/apk/debug/app-debug.apk
```

هذا APK تجريبي موقّع بمفتاح Debug، وليس ملف التوزيع النهائي. لم يُنسخ أي APK قديم من `public` على أنه ناتج جديد.

لتجهيز الأصول فقط، بدون الادعاء بإنتاج APK:

```sh
pnpm android:prepare
```

## إصدار التوزيع

استخدم مفتاح التوقيع الذي يتحكم فيه المالك، وبالأخص المفتاح نفسه إن كان هناك تطبيق مثبت بالفعل بنفس هوية الحزمة. إعدادات التوقيع في `android/keystore.properties` تبقى خارج Git. لا ترسل كلمات المرور في المحادثة، ولا تنشئ مفتاحًا بديلًا تلقائيًا. إذا استُخدمت قيم التوقيع الثابتة من السكربت القديم لمفتاح حقيقي، يحتاج ذلك إلى مراجعة أمان للمفتاح وخطة تحديث؛ لا تستبدله تلقائيًا. راجع `versionCode` ورقم الإصدار قبل توزيع تحديث.

```sh
pnpm apk:release
```

الناتج عند نجاح البناء:

```text
artifacts/mydan/android/app/build/outputs/apk/release/app-release.apk
```

يوجد `pnpm aab:release` إذا تقرر لاحقًا مسار متجر يتطلب AAB. لا يتضمن بناء ملف محلي نشرًا على متجر أو توزيعًا خارجيًا.

## الحالة المتحققة في بيئة المعالجة

وافق المالك على ترخيص SDK، وتم تثبيت أدوات البناء ونجح استخراج APK Native من المصدر. النسخة الحالية **Mydan Preview** تجريبية، بهوية `com.mydan.supervisor.preview` وتوقيع Debug، لتُثبَّت بجوار نسخة Release.

نجح فحص التوقيع v1/v2 ومحاذاة الحزمة وسلامة ZIP واسم الحزمة والأصول المدمجة. التفاصيل والبصمة وحدود الفحص في [نتيجة استخراج APK](mydan-apk-build-status.md). لم تُختبر على هاتف ولم تُطبق مسودات Supabase بعد.

## اختبارات قبول APK قبل التوزيع

اختبر APK نفسه على هاتف: الدخول وتغيير/استعادة كلمة المرور، اعتماد الجهاز، أذونات الكاميرا والموقع، رفع الصور، العودة من الخلفية، العمليات المعلقة وإعادة المزامنة، الروابط الخارجية وزر الرجوع، ومنع دخول شركة أخرى. اختبر ترقيته فوق نسخة سابقة بالمفتاح ورقم الإصدار الصحيحين.

ربط UUID ليس إثبات هوية ماديًا للجهاز، ولا يثبت GPS وحده الحضور الفعلي. إشعارات التطبيق الداخلية موجودة؛ Web Push لا يُفترض أنه يعمل تلقائيًا داخل Android WebView، والإشعارات الأصلية تحتاج تكاملًا واختبارًا مستقلين إن طُلبت.

يتطلب تشغيل نسخة الإصلاحات مراجعة مسودة قاعدة البيانات والخدمات المتوافقة أولًا. راجع [سجل الإصلاحات](mydan-remediation.md) و[العقد الهندسي](mydan-engineering-contract.md). لا توجد موافقة ضمنية على SQL خارجي أو نشر.
